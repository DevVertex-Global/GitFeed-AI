## 💙 Our Core Vision & Dedicated Message to Students

> **"If you have a smartphone, a terminal (like Termux), and a passion to learn, you have everything you need to build the future."**

### 🎯 Who is this built for?
**GitFeed-AI** was **not** created as a commercial product or exclusive enterprise platform. It was built with deep respect and dedication toward **students, self-taught coders, and beginner developers** worldwide.

Many new learners feel discouraged because they lack high-end laptops, paid servers, or custom `.com` domains. We designed GitFeed-AI entirely on mobile devices using 100% free hosting, open APIs, and free domain resources to prove one simple point:  
👉 **You do NOT need money or expensive gear to build modern, beautiful, AI-powered applications.**

---

## 🛠️ Tech Stack & Tools Breakdown

To make this project lightweight, fast, and completely free, we carefully selected a stack of accessible tools that any student can set up easily on an Android phone (using Termux) or a basic computer:

| Tool / Technology | What It Does in GitFeed-AI | Why We Chose It |
| :--- | :--- | :--- |
| **🐍 Python & Flask** | Lightweight backend server handling multi-page routing (`/`, `/trending`, `/starred`, `/profile`, `/settings`, `/privacy`). | Beginner-friendly, highly customizable, and runs smoothly inside Termux on mobile. |
| **📱 Termux (Android)** | Primary mobile terminal development environment. | Proves that a personal computer is not mandatory for real-world web development. |
| **🌐 HTML5, CSS3 & JS** | Powers our custom **Liquid Glass UI**, modular layouts (`base.html`), and instant theme toggling. | Built using pure vanilla web technologies without heavy frameworks for maximum performance. |
| **🤖 Google Gemini API** | Integrated for AI-driven repository analysis, code summaries, and project evaluations. | Gives students hands-on experience integrating free-tier generative AI models. |
| **🐙 GitHub REST API** | Fetches live user profiles, public feeds, repository stats, and handles real-time starring. | Eliminates the need for a separate server database by leveraging GitHub directly. |
| **🔐 Browser LocalStorage** | Securely stores user access tokens and API keys locally on the user's device. | Ensures complete privacy and zero server-side credential storage. |

## 🌐 The Domain System: Why Did We Choose a Free Domain over a Paid Top-Level Domain (.com)?

Many developers might ask:  
> *"Why use a free domain instead of purchasing a premium .com or top-level domain?"*

#### 📢 Our Honest & Respectful Answer:

1. **100% Zero-Budget Proof of Concept:**  
   If we purchased a `.com` domain or paid cloud server, it would defeat our core message to students. We wanted to show learners that **anyone can deploy a complete, functional web app for $0**.
2. **Reproducibility for Learners:**  
   Every student who clones this repository can deploy it on free platforms (like Vercel, Netlify, Render, or Ngrok) using free domain names without entering a credit card.
3. **No Financial Barrier:**  
   By strictly using free-tier domains, we ensure that the project remains open, accessible, and reproducible for developers from all economic backgrounds.

## 🔒 Security Protocols & Addressing Privacy Concerns

We know experienced developers or critics might naturally ask:
> *"Is it risky to enter API tokens on a site hosted on a free domain?"*

#### 🛡️ Our Security Architecture & Guarantees:

1. **Zero-Database Architecture (BYOK - Bring Your Own Key):**
   - **We have ZERO backend databases.** We do not log, collect, or store your GitHub Personal Access Tokens or Gemini API Keys on any server.
   - All credentials stay **strictly encrypted inside your browser's LocalStorage**.

2. **Client-Side Obfuscation & Eye-Toggle Masking:**
   - In **Settings > Privacy & Security**, input fields are default-masked (`••••••••`) like passwords.
   - An interactive Eye (👁️) toggle prevents accidental token leaks during live streams or screen sharing.

3. **Direct API Communication:**
   - Your token never touches a middleman server. Encrypted requests go directly from **your browser** to **official API endpoints** (`api.github.com` & Google AI APIs).

> ⚠️ **Feeling Skeptical?**  
> We completely respect your privacy choices! If you feel uncomfortable entering your main GitHub token:
> - You can browse the public feeds **without adding any token**.
> - Or, you can use a secondary/dummy GitHub token with read-only permissions!
